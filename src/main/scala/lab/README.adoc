----
Why Proper English Matters

Behavior scenarios are meant to be readable and expressive. Steps
are also meant to be reusable.

Poor grammar, misspellings, and inconsistent phrasing can ruin the
benefits of behavior specification. Scenarios can become confusing.
Improper steps could be used.

=== Automation Panda
* https://automationpanda.com/[Automation panda]

----
 Use same short names for Persons in different roles.
admin -> Amy, user -> Bob.
It's much easier to remember that than "The user"


 Use Acronyms for systems/components maybe with a dash
UI "Users Overview"  displays user "john doe" or ACME.
For better clarity, such identifiers should be in uppercase

 Within generic "And" steps,  can be used at the beginning of the statement ... in place of the name
